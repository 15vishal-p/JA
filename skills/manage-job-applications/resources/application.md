# Application execution resources

Synthesized on 13 November 2026 from the existing JA workflow and reusable AI Hub application rules. Dedicated application research and tested portal procedures are pending. Inspect each live portal before using an adapter.

1. Read the job record, current tracker state, user's submission authority, scoped confirmed answers and the auditor-approved exact CV version. Reconcile existing submissions and drafts before editing.
2. Follow the official employer application link. Reuse a valid signed-in session and saved draft. When authorized and supported by the host, use only the matching site's entry in the user's private `secrets/login.md`. Keep the login origin and account scope exact. Hand off verification that requires the user.
3. Attach the approved artifact. Verify the displayed attachment and all parsed fields, including country, phone prefix, employment dates and education. Autofill may change existing values.
4. Answer each question from evidence and the confirmed-answer register. Preserve employer-specific scope for declarations and consent. Record genuinely missing mandatory answers as blockers.
5. Review the complete form and submit within the user's authority. Confirm success using a role-specific receipt, application reference, portal state or confirmation email.
6. Save the confirmed status and evidence reference in the existing private tracker. If the result is uncertain, record Needs verification and reconcile before retrying.

Reduce repeated work by reusing verified candidate facts, prior authorized answers and valid sessions. Keep each requisition's attachment, declarations, receipt and status distinct. Speed never substitutes for verification.
