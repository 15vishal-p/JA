# CV Creation

Create the complete, role-specific CV from the verified candidate record and live JD. Read [CV research](../../resources/cv-creation.md), the user's current CV rules and the Job Search handoff. Preserve official employment titles, dates, education and factual achievements. Ask focused questions when a material claim lacks evidence.

## Work

1. Recheck the target employer/requisition and current JD. Select the strongest source CV and relevant verified work/project evidence. Map each important requirement to supported content before writing.
2. Tailor the headline, summary, experience emphasis, skills, projects and section order to the role. Use the JD's terminology where it accurately describes the candidate's work. Quantify scope and results only from verified records. Distinguish hands-on work from coursework, project work and learning.
3. For finance/accounting roles, normally place Experience before Projects and develop distinct substantive bullets showing processes, tools, controls and outcomes. For engineering or technical career changes, foreground relevant technical projects and keep unrelated employment concise. For analytics, choose the ordering that exposes the strongest relevant evidence. Apply the user's specific project selection and depth rules when supplied.
4. Preserve the actual residence. State a different target city as a relocation preference or target location. Use verified language levels and country-specific eligibility facts. Keep internal scores and audit gaps in working records, while presenting supported strengths clearly in the CV.
5. Follow the user's editor, template, file type and page requirements. A requirement for direct FlowCV export or a two-page Slovakia CV belongs to that user's configuration. Lock a shared active template to one editor and preserve previous exports before retargeting it.
6. Export a distinct file such as `Company_Role_ReqID_Date_CV.pdf`. Check selectable text, reading order and every rendered page. Correct clipping, broken links/glyphs, awkward splits, large accidental blank areas and sparse sections with relevant verified content or layout adjustments. Ask for missing substance when needed. Preserve readable typography.
7. Archive the exact exported artifact in authorized storage and verify its returned link or local path. Record the editor/export provenance, version, source facts and any unresolved issue. Hand it to the independent CV Audit role before application use.

## Handoff to CV Audit

Provide employer/requisition, current JD snapshot/source, exact final file reference and version or checksum where available, export provenance, candidate evidence references, requirement/content mapping and applicable user rules. Set `CV exported` or `CV archived` as supported by evidence. The auditor decides whether that artifact passes.

When the auditor reports defects, fix their root cause and export a new version. Any content, layout or file replacement invalidates the previous audit. Return the replacement for a fresh audit and preserve historically submitted files.
